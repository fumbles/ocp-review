## 1. Project overview

**OCP Mastery** is a single-page React study app for the Red Hat OpenShift
Container Platform (OCP 4.21 / EX280 / DO180) exam. It is served as a static
site from a pre-built `dist/` directory inside an nginx container.

- Docker Hub image: `fumbles/ocp-review:latest`
- Live URL: `https://ocp-review.yamlwrangler.com`

The app has seven pages (tabs), all driven by pure JavaScript data files —
no backend, no database, no API calls.

## 4. Local development

### Prerequisites

- Node.js ≥ 18, npm ≥ 9
- Docker Desktop with buildx (for publishing)
- `oc` CLI (for cluster operations)

### Start the dev server

```bash
cd app
npm install          # first time only
npm run dev          # Vite dev server → http://localhost:5173
```

Hot-reload is enabled. Editing any file under `src/data/` or `src/components/`
refreshes the browser instantly.

### Validate a production build locally

```bash
cd app
npm run build        # outputs to app/dist/
npm run preview      # serves dist/ at http://localhost:4173
```

The `build` step **must pass with no errors** before publishing. The
chunk-size warning (`> 500 kB`) is pre-existing and acceptable — do not
attempt to silence it by splitting bundles unless asked.

### Lint

```bash
cd app && npm run lint
```

### 5.1 `glossary.js`

```js
export const glossaryTerms = [
  {
    term: "Pod",          // display name — used as heading and sort key
    abbr: "...",          // optional — expands the abbreviation
    cat:  "core",         // category string — must be in GL_CATS (see §6.4)
    def:  "...",          // definition text (plain string, no HTML)
    doc:  "https://..."   // optional — external documentation URL
  },
  ...
]
```

**Categories** (`GL_CATS` in `GlossaryPage.jsx`):

| Key | Display label |
|---|---|
| `core` | K8s Core |
| `ocp` | OpenShift |
| `operators` | Operators & OLM |
| `networking` | Networking |
| `storage` | Storage |
| `security` | Security |
| `monitoring` | Monitoring |
| `builds` | Builds & CI/CD |
| `advanced` | Advanced / Platform |
| `odf` | Data Foundation (ODF) |
| `backup` | Backup & Restore |
| `virt` | Virtualization |
| `multicluster` | Multi-Cluster (ACM) |
| `hcp` | Hosted Control Planes |
| `acronym` | Acronyms |

> **Adding a new category:** add the `key: 'Label'` pair to `GL_CATS` in
> `app/src/components/pages/GlossaryPage.jsx` AND update the header comment
> on line 4 of `glossary.js`.

**Doc URL format** — all Red Hat docs must use:
```
https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/...
```
Never use the old `docs.openshift.com/container-platform/4.x/` format.

### 5.2 `topics.js` — Learn page

```js
export const topics = [
  {
    id:      'k8s-arch',           // unique string, kebab-case
    label:   'K8s Architecture',   // tab/sidebar display name
    content: `                     // template-literal HTML string
      <h3>Section Heading</h3>
      <p class="topic-desc">Intro paragraph.</p>

      <div class="section-title">Sub-section</div>
      <div class="definition-card"><h4>Term</h4><p>Body.</p></div>
      <div class="tip"><strong>💡 Tip:</strong> text</div>
      <div class="warn"><strong>⚠️ Warning:</strong> text</div>
      <pre><span class="c"># comment</span>
oc get pods</pre>
    `,
  },
  ...
]
```

**CSS classes available in content strings:**

| Class | Purpose |
|---|---|
| `topic-desc` | Intro paragraph below the `<h3>` |
| `section-title` | Bold section divider |
| `definition-card` | Card with `<h4>` heading and `<p>` body |
| `tip` | Green info box |
| `warn` | Amber/red warning box |
| `pre` / `<pre>` | Code block; use `<span class="c">` for comments |

> All HTML in content strings is rendered via `dangerouslySetInnerHTML`.
> Keep it simple — no inline scripts or event handlers.

## 6. Component map

### 6.1 `App.jsx`
Manages the Carbon `Theme` toggle (`white` ↔ `g100`). Persists the chosen
theme to `localStorage` under the key `ocp-theme`. Renders `<Shell>`.

### 6.2 `Shell.jsx`
Owns all navigation state. Contains:
- `PAGES` array — the ordered list of `{ id, label }` entries for the nav.
- `PAGE_COMPONENTS` map — maps each page `id` to its JSX element.
- `Header` / `HeaderNavigation` / `SideNav` — Carbon nav components.
- `navigate(id)` function — sets `activePage`, closes side nav, scrolls top.

**To add a new page**, edit only `Shell.jsx` and create the page component.
See [§10](#10-adding-a-new-page--nav-tab).

### 6.3 `LearnPage.jsx`
Reads `topics` from `topics.js`. Renders a left-hand topic list and a content
panel. Content is rendered with `dangerouslySetInnerHTML`.

### 6.4 `GlossaryPage.jsx`
Reads `glossaryTerms` from `glossary.js`. Contains `GL_CATS` — the category
filter map. Filtered + sorted alphabetically via `useMemo`. Search matches on
`term`, `abbr`, and `def`.

### 6.5 `FlashcardsPage.jsx`
Reads `allCards` from `flashcards.js`. Supports tag filtering, shuffle, and
answer reveal.

### 6.6 `WalkthroughsPage.jsx`
Reads `walkthroughs` from `walkthroughs.js`. List view → step-by-step detail
view.

### 6.7 `TroubleshootingPage.jsx`
Reads `troubleshootingSections` from `troubleshooting.js`. Accordion layout
with basic/expert command tabs.

### 6.8 `PracticeExamsPage.jsx`
Reads `practiceExams` from `practiceExams.js`. Challenge list → task detail
with hint/solution toggle, checkbox completion tracking, and optional links bar
(`.ocp-pe__links` from `_practice-exams.scss`).

### 6.9 `HomePage.jsx`
Static content page. Contains the OCP 4.21 version tag, external links grid
(docs, cert map), and nav cards including Practice Challenges.

## 7. Styling conventions

- **Do not** write plain CSS files. All styles go in `app/src/styles/`.
- Each page has its own partial: `_<page>.scss`. Import it in `index.scss`
  with `@use './<partial>'` (no leading underscore, no extension).
- Use Carbon design tokens (`var(--cds-*)`) for colors, spacing, and
  typography rather than hardcoded values wherever possible.
- The brand override block at the bottom of `index.scss` sets Carbon's
  interactive/link tokens to Red Hat red (`#ee0000`). Do not change this.
- IBM Plex fonts are loaded from Google Fonts CDN in `app/index.html` because
  Carbon's bundled `@font-face` uses webpack-resolver tilde URLs that Vite
  cannot resolve. The `$css--font-face: false` config in `index.scss`
  suppresses those rules.

## 8. Build & publish

### One-command publish

```bash
# From repo root
./build.sh                        # builds latest, targets linux/amd64,arm64
./build.sh v1.2.3                 # custom tag
./build.sh v1.2.3 linux/amd64    # single platform
```

The script:
1. Checks Docker is running.
2. Runs `npm ci && npm run build` inside `app/` (produces `app/dist/`).
3. Prompts for confirmation.
4. Runs `docker buildx build --platform ... --push` to Docker Hub.

### Why Vite runs locally (not in Docker)

The `Dockerfile` is single-stage (nginx only) — it does **not** run Node.
Running Node inside a QEMU-emulated `linux/amd64` layer on an Apple Silicon
host causes a QEMU segfault. Building Vite locally and `COPY`ing the resulting
`dist/` into the image sidesteps this entirely.

### Dockerfile summary

```dockerfile
FROM nginxinc/nginx-unprivileged:alpine   # non-root; listens on 8080
COPY app/dist /usr/share/nginx/html
COPY app/nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 8080
```

### nginx config highlights (`app/nginx.conf`)

- `index.html` — `no-cache, no-store` (new deployments always picked up).
- JS/CSS — `no-store, no-cache` (hashed filenames + aggressive revalidation).
- Images/fonts — `1y, immutable` (content-hashed, safe to cache forever).
- SPA fallback: all paths fall through to `index.html`.
- Security headers: `X-Frame-Options`, `X-Content-Type-Options`, `X-XSS-Protection`.
- Gzip enabled for CSS, JS, JSON.

## 9. OpenShift deployment

### First deploy

```bash
oc apply -f deployment.yaml
oc apply -f external-route.yaml   # only if the public route is needed
```

`deployment.yaml` creates three objects in one file:

| Object | Details |
|---|---|
| `Deployment/ocp-review` | 2 replicas, RollingUpdate (maxUnavailable:1 maxSurge:1) |
| `Service/ocp-review` | ClusterIP, port 80 → targetPort 8080 |
| `Route/ocp-review` | Edge TLS, insecureEdgeTerminationPolicy: Redirect |

`external-route.yaml` adds a second Route with the custom hostname
`ocp-review.yamlwrangler.com` (edge TLS, same redirect policy).

### Rolling out a new image

After publishing a new `fumbles/ocp-review:latest` to Docker Hub:

```bash
oc rollout restart deployment/ocp-review
oc rollout status deployment/ocp-review    # watch progress
```

### Resource requests/limits

```yaml
requests: { cpu: 50m,  memory: 32Mi }
limits:   { cpu: 200m, memory: 64Mi }
```

The app is purely static (nginx), so these are intentionally small.

## 10. Adding a new page / nav tab

1. **Create the page component** at
   `app/src/components/pages/MyNewPage.jsx`.

2. **Add to `Shell.jsx`** (two places):

   ```js
   // In the PAGES array (controls nav order):
   { id: 'mynew', label: 'My New Page' },

   // In PAGE_COMPONENTS:
   mynew: <MyNewPage />,
   ```

   Also add the import at the top of `Shell.jsx`.

3. **Create a data file** at `app/src/data/myNew.js` if content-driven,
   following the existing export conventions.

4. **Create a style partial** at `app/src/styles/_my-new.scss` and add
   `@use './my-new';` to `app/src/styles/index.scss`.

5. **Run `npm run build`** to confirm no errors before committing.

## 11. Constraints & conventions

| Rule | Reason |
|---|---|
| Carbon v11 components only (`@carbon/react`) | Consistent design system |
| No external UI libraries | Bundle size + coherence |
| All doc URLs use `docs.redhat.com/en/documentation/openshift_container_platform/4.21/` | Consistent linking to current OCP version |
| Data-only changes never require component edits (except `GL_CATS` for new glossary categories) | Content is decoupled from UI |
| `npm run build` must pass with zero errors before publishing | Required by `build.sh` |
| Minimal changes — do not refactor unrelated code | Surgical edits only |
| No inline scripts or event handlers in `dangerouslySetInnerHTML` content | Security |
| nginx config lives at `app/nginx.conf` — copied into Docker at build time | Single source of truth |
| `app/dist/` is git-ignored — always regenerated by `build.sh` | No stale artefacts committed |
